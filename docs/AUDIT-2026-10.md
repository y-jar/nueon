# Audit — October 2026

A pass over the app shell, editor, dictionary grid and the recent tab-bar work,
triggered by the column-context-menu bug. Findings are ranked by severity, each
with a file reference and a recommendation. Nothing here is fixed except what a
commit says it fixed; treat the rest as a to-do list to triage.

## Findings

### Medium

**1. `recentRecord` is fire-and-forget with no error handling.**
`void api.recentRecord(...)` at `src/lib/tabs.svelte.ts:139,150,161,172,182,193`
writes the "recently opened" list on every note/table open and never catches a
rejection. It is best-effort, so a failed IPC write becomes an unhandled promise
rejection — previously silent, now surfaced in the status bar by the global
handler added in `480b91e`. Recommendation: `void api.recentRecord(...).catch(() => {})`,
or a tiny `recordRecent(entry)` helper that swallows errors once.

### Low

**2. The setup wizard has no Escape handling.**
`src/components/SetupWizard.svelte` is closed only by its own buttons; it registers
no `keydown` handler, unlike every other modal. Low impact (it is an onboarding
screen), but inconsistent with the modal contract.

**3. `{@const}` inside conditionally-destroyed blocks (the column-menu pattern).**
The column menu used `{@const col = menu.column}` inside a branch that is destroyed
when `menu` clears; that was the suspect for the stuck-menu bug and is now replaced
by a `$derived` (`src/components/ContextMenu.svelte`). Two more instances use the
same shape but reference string-derived values rather than a nullable object, so they
are low risk: `src/components/GitPanel.svelte:242` (`{@const view = truncate(diff)}`
in an `{:else}` branch) and `:265` (`{@const commitView = truncate(showOutput)}` in
an `{#if showId}`). Leave them, but treat `{@const}` over a nullable value in a
destroyable branch as a banned pattern.

**4. Menus have no keyboard navigation.**
The context menu is `role="menu"` with `<button>` children but no `role="menuitem"`,
no roving tabindex, and no Arrow/Enter handling. Escape and outside-click work;
keyboard users cannot move to and activate an item. This is the other half of the
reported bug ("action enter does nothing"). Recommendation: give the menu focus on
open (autofocus), add Arrow-up/down + Home/End + Enter, and close on Escape as today.

### Observability (resolved)

**5. Silent render errors.** There was no global `error` or `unhandledrejection`
handler, so a render error (the likely cause of a stuck overlay) left no trace.
`480b91e` adds both, logging to the console and showing `Error: …` in the status bar.

## Probe coverage gaps (dismissal contract)

One dismissal probe exists (96, column menu). The other menu kinds and modals have
no Escape/outside-click/action proof, even though the tab menu is exercised
indirectly by 91/93:

- root menu, note/node menu, table menu, editor menu — no dismissal probe.
- Every modal (`AddWordModal`, `DeleteWordModal`, `TrashModal`, `SettingsModal`,
  `ConfirmDialog`, `KeybindCaptureModal`, `ImportWizardModal`, `SetupWizard`) — no
  Escape probe; `SetupWizard` is also missing the handler itself (finding 2).
- `Popover` (sidebar export menu, editor toolbar menus) — no click-outside/Escape probe.
- Tag/value suggestion dropdown (`SuggestionList`, `PillCell`) — no dismissal probe.

Recommendation: one shared dismissal probe that walks each overlay kind and asserts
"opens, then closes on Escape, on an outside click, and on an action", rather than
one bespoke probe per overlay.

## Recommendations

1. Swallow `recentRecord` errors (finding 1).
2. Add keyboard navigation to the context menu and give it focus on open (finding 4).
3. Add Escape to `SetupWizard` (finding 2).
4. Write the shared dismissal probe for the remaining overlay kinds.
5. When triaging any of the above, add the `{@const}`-over-nullable ban to `standards.md`
   (part of the docs phase).
